# A 股行情系统 MVP 设计

## 1. 文档信息

- 日期：2026 年 8 月 4 日
- 状态：已完成需求与界面方向确认，等待书面设计审阅
- 目标版本：MVP 第一版
- 使用场景：个人 A 股研究与行情查看
- 数据成本约束：只使用免费公开数据源
- 部署方向：本地优先，后续允许迁移到 Linux 服务器

## 2. 产品目标

第一版建立一个可信、可扩展的 A 股行情底座，完成以下核心闭环：

1. 获取沪深京 A 股股票列表和当前行情；
2. 在交易时段每分钟刷新一次全市场行情快照；
3. 支持按股票代码或名称搜索；
4. 点击股票进入详情页；
5. 在详情页查看今日分钟 K 线以及多周期历史 K 线；
6. 保存历史日线、全市场分钟快照和已经取得的原生分钟 K 线；
7. 为后续增加技术指标和条件筛选建立稳定的数据与接口边界。

第一版的重点不是预测涨跌，而是保证行情数据的来源、时间、含义和质量能够被解释。

## 3. 第一版范围

### 3.1 股票列表页

列表页展示全部沪深京 A 股。每只股票占一行，整行可点击进入详情页。

固定字段如下：

| 字段 | 含义 |
| --- | --- |
| 股票 | 股票名称、代码和所属市场 |
| 最新价 | 最近一次全市场快照中的最新成交价 |
| 涨跌幅 | 相对昨收的涨跌百分比 |
| 涨跌额 | 相对昨收的价格变化 |
| 今日区间 | 当日最低价至最高价 |
| 成交量 | 当日累计成交量 |
| 成交额 | 当日累计成交额 |
| 换手率 | 数据源返回的当日换手率 |
| 总市值 | 数据源返回的总市值 |

列表页还包含：

- 股票总数、上涨数、下跌数、平盘数和全市场成交额概览；
- 代码或名称搜索；
- 市场过滤；
- 基础排序；
- 行情状态和最后成功更新时间；
- 分页或虚拟滚动，避免一次渲染数千行；
- 中国市场配色习惯：红色表示上涨，绿色表示下跌。

左侧菜单第一版只显示“全部股票”，不展示尚未实现的筛选、收藏、监控或设置入口。

### 3.2 个股详情页

详情页包含：

- 股票名称、代码和所属交易所；
- 最新价、涨跌额和涨跌幅；
- 今开、最高、最低、昨收、成交量、成交额、换手率和总市值；
- 行情状态和最后更新时间；
- 返回全部股票；
- 搜索并切换到其他股票；
- K 线图和成交量图。

支持以下周期：

- 今日；
- 1 分钟；
- 5 分钟；
- 15 分钟；
- 30 分钟；
- 60 分钟；
- 日 K；
- 周 K；
- 月 K。

“今日”具有明确语义：

- 只显示当前交易日；
- 一根 K 线柱代表 1 分钟；
- K 线实体表示该分钟开盘价与收盘价；
- 上下影线表示该分钟最高价与最低价；
- 下方成交量柱表示该分钟成交量；
- 只有数据源明确返回当前未结束分钟柱时，才将最后一根标记为动态；否则只展示已经结束的分钟柱；
- 页面每分钟请求一次新增数据。

K 线交互包含：

- 放大；
- 缩小；
- 鼠标滚轮缩放；
- 拖动查看历史；
- 底部范围选择；
- 悬浮查看单根 K 线的时间、开高低收、成交量和成交额。

第一版不展示任何技术指标。

## 4. 明确不在第一版实现的内容

- MA、EMA、MACD、RSI、KDJ、BOLL 等技术指标；
- 自定义条件筛选器；
- 历史条件命中记录；
- 收藏和自选股；
- 消息提醒；
- 用户登录和多用户权限；
- 自动交易、下单或券商账户连接；
- 策略回测；
- Level-2、逐笔成交和逐笔委托；
- 付费行情源；
- 移动端专项适配。

这些能力以后在稳定的行情底座上逐项增加，不提前放置空菜单或不可用按钮。

## 5. 数据真实性边界

### 5.1 三类数据必须分开

系统区分三类数据，禁止混用：

1. **全市场行情快照**：某一采样时刻每只股票的最新价、当日累计成交量、当日最高价等；
2. **原生分钟 K**：数据源按每分钟成交过程汇总出的开高低收和分钟成交量；
3. **历史日 K**：数据源按交易日汇总出的日线数据。

每分钟获取一次全市场快照，无法还原该分钟内部完整的最高价和最低价。因此，全市场快照只按快照保存，不伪装成原生分钟 K。

### 5.2 第一版可保证的覆盖范围

- 全市场行情快照：交易时段每分钟获取一次，自系统上线后永久保存；
- 历史日 K：初始化最近 60 个交易日，之后每日追加；
- 原生 1 分钟 K：免费数据源可回看约最近 5 个交易日；
- 原生 5 分钟及以上 K：在免费数据源允许的时间范围内回补；
- 个股详情页：打开任意股票时，按需获取其近期原生分钟 K，并将已经取得的数据永久保存。

第一版不承诺免费获取全市场所有股票连续 60 个交易日的原生 1 分钟 K，也不承诺在后台逐只请求数千只股票来补齐原生分钟 K。该行为容易触发限流，且与“完全免费、稳定运行”的约束冲突。

### 5.3 数据质量标记

每批数据都记录：

- 数据源；
- 本地获取时间；
- 数据对应的市场时间；
- 数据类型；
- 是否完整；
- 是否过期；
- 错误或缺失原因。

页面只显示明确取得的数据。接口失败时保留上一批有效数据并标记“数据可能已过期”，不得用零值或推测值填充。

## 6. 技术路线比较

### 6.1 方案 A：本地优先轻量架构

- React 与 TypeScript 构建前端；
- Python 与 FastAPI 构建接口和采集服务；
- Apache ECharts 绘制 K 线和成交量；
- DuckDB 保存热数据、元数据和查询索引；
- Parquet 保存长期大体量行情分区；
- 单进程负责写入，避免 DuckDB 多进程写入冲突。

优点是免费、部署简单、适合本地研究、数据分析性能好，后续也可以迁移到服务器。缺点是本机必须在交易时段保持运行，才能连续采集全市场快照。

### 6.2 方案 B：传统服务架构

- React；
- FastAPI；
- PostgreSQL；
- Redis；
- 独立任务进程。

该方案适合多人使用和长期服务器部署，但第一版的安装、运行和维护成本较高。

### 6.3 方案 C：大规模行情架构

- React；
- FastAPI；
- ClickHouse；
- 分布式采集和任务调度。

该方案适合多年全市场分钟行情和复杂回测，但当前明显过度设计。

### 6.4 已选方案

采用方案 A。

## 7. 总体架构

```text
公开行情数据源
      │
      ▼
数据源适配器
      │ 统一代码、字段、单位、时间和数据质量
      ▼
采集与校验服务
      │
      ├── 全市场快照采集器
      ├── 历史日 K 回补器
      ├── 个股分钟 K 获取器
      └── 交易时段调度器
      │
      ▼
DuckDB 热数据与元数据
      │
      ├── 当前行情
      ├── 当日采集数据
      ├── 股票基础信息
      └── 采集状态与质量记录
      │
      ▼ 收盘后归档
Parquet 长期行情分区
      │
      ▼
FastAPI 查询接口
      │
      ▼
React 列表页与个股详情页
```

## 8. 组件边界

### 8.1 数据源适配器

职责：

- 隔离 AKShare、东方财富、新浪或其他公开端点的字段差异；
- 将股票代码统一为“代码 + 市场”；
- 统一价格、成交量和成交额单位；
- 返回结构化错误，不让页面直接依赖第三方字段；
- 记录每条数据的来源与市场时间。

页面、存储和业务接口不得直接调用 AKShare 函数。

实时快照优先使用东方财富相关公开端点；历史日 K 和分钟 K 通过同一适配层获取。备用数据源只在字段语义可验证时启用，不以不同口径的数据强行覆盖主数据。

### 8.2 股票主数据服务

职责：

- 维护沪深京 A 股代码、名称、市场和上市状态；
- 处理新增上市、退市、暂停上市和名称变化；
- 为搜索和路由提供稳定标识。

### 8.3 全市场快照采集器

职责：

- 仅在交易日与交易时段运行；
- 每分钟获取一次全市场快照；
- 校验股票数量、代码唯一性、时间戳和关键字段；
- 原样保存快照，不转换为原生分钟 K；
- 更新列表页使用的最新行情表。

交易时段使用北京时间：

- 上午：09:30 至 11:30；
- 下午：13:00 至 15:00；
- 午间休市、收盘后、周末和非交易日不执行分钟轮询。

### 8.4 历史日 K 回补器

职责：

- 首次启动时回补最近 60 个交易日；
- 以较低速率分批获取，避免公开接口限流；
- 支持续传、幂等写入和失败重试；
- 收盘后追加当天正式日 K；
- 支持不复权、前复权和后复权的数据标识。

### 8.5 个股分钟 K 服务

职责：

- 在详情页请求时获取股票的原生分钟 K；
- 缓存免费数据源可提供的近期分钟历史；
- 交易时段每分钟补充当前股票的新分钟柱；
- 区分已结束分钟柱和数据源明确提供的当前动态分钟柱；
- 将已经取得的原生分钟 K 永久保存；
- 同一股票的并发请求合并为一次上游请求。

### 8.6 数据查询接口

职责：

- 为前端提供稳定的分页、搜索、排序和 K 线结构；
- 隐藏底层 DuckDB、Parquet 和第三方接口；
- 返回最后更新时间和质量状态；
- 对相同查询提供短时缓存。

### 8.7 前端

职责：

- 呈现已经确认的 HeroUI 浅色平衡型界面；
- 列表页每分钟刷新一次；
- 详情页“今日”视图每分钟刷新一次；
- 使用 ECharts 绘制 K 线、成交量、缩放和提示信息；
- 明确展示加载中、无结果、市场休市、数据过期和接口失败状态。

## 9. 数据流

### 9.1 首次启动

1. 创建本地数据库和数据目录；
2. 获取股票主数据；
3. 获取一批全市场快照，使列表页尽快可用；
4. 在后台分批回补最近 60 个交易日的日 K；
5. 记录回补进度，允许中断后继续；
6. 页面显示初始化进度，但不阻塞已经可用的列表行情。

### 9.2 交易时段全市场更新

1. 调度器触发全市场快照采集；
2. 适配器统一字段和单位；
3. 校验股票数量、代码、价格与时间；
4. 将原始规范化快照写入当日热数据；
5. 原子更新“每只股票最新行情”；
6. 前端下一次轮询读取最新数据；
7. 失败时继续提供上一批有效数据并显示过期状态。

### 9.3 打开个股详情页

1. 查询股票基础信息与最新行情；
2. 查询本地已有的对应周期 K 线；
3. 若数据缺失或过期，触发单股上游请求；
4. 将新取得的原生 K 线幂等写入；
5. 返回 K 线、成交量、数据源和最后更新时间；
6. “今日”视图在交易时段每分钟请求新增分钟柱。

### 9.4 收盘后归档

1. 停止分钟轮询；
2. 获取并校验当天正式日 K；
3. 将当日全市场快照从热数据归档到按交易日分区的 Parquet；
4. 对当天采集批次生成完整性报告；
5. 保留异常记录供后续排查。

## 10. 存储设计

### 10.1 DuckDB 热数据和元数据

核心逻辑表：

#### `stock_master`

- `code`
- `market`
- `name`
- `list_status`
- `list_date`
- `updated_at`

唯一键：`market + code`。

#### `latest_quote`

- `code`
- `market`
- `market_time`
- `latest_price`
- `change_amount`
- `change_percent`
- `open_price`
- `high_price`
- `low_price`
- `previous_close`
- `volume`
- `amount`
- `turnover_rate`
- `total_market_cap`
- `source`
- `acquired_at`
- `quality_status`

每只股票只保留最近一条，用于快速读取列表。

#### `quote_snapshot_hot`

保存当前交易日每分钟的全市场规范化快照。

唯一键：`market + code + market_time`。

#### `daily_bar_hot`

保存近期日 K 和回补过程中的热数据。

唯一键：`market + code + trade_date + adjustment`。

#### `native_minute_bar_hot`

保存近期原生分钟 K。

唯一键：`market + code + period + bar_time + adjustment`。

#### `ingestion_run`

记录采集类型、开始时间、结束时间、数据源、请求结果、行数、错误和质量状态。

### 10.2 Parquet 长期分区

长期数据按类型和日期分区：

```text
data/
  snapshots/trade_date=2026-08-04/
  daily_bars/year=2026/
  minute_bars/trade_date=2026-08-04/
```

DuckDB 通过外部视图查询 Parquet。归档过程先写临时文件、完成校验后再原子替换，避免产生半文件。

### 10.3 单写入者约束

MVP 只运行一个后端进程。采集任务和接口在同一进程内协调，由单一写入队列串行落库。前端可以并发读取，但不启动多个独立后端写进程。

## 11. HTTP 接口设计

### 11.1 市场概览

`GET /api/market/summary`

返回股票总数、上涨数、下跌数、平盘数、全市场成交额、市场状态和最后更新时间。

### 11.2 股票列表

`GET /api/market/stocks`

查询参数：

- `query`：代码或名称；
- `market`：全部、沪、深、京；
- `sort_by`：允许排序的字段；
- `sort_order`：升序或降序；
- `page`；
- `page_size`。

默认每页 50 条。搜索支持代码前缀和名称包含匹配。

### 11.3 个股概览

`GET /api/stocks/{market}/{code}`

返回股票基础信息、最新行情、数据质量和最后更新时间。

### 11.4 个股 K 线

`GET /api/stocks/{market}/{code}/bars`

查询参数：

- `period`：`1m`、`5m`、`15m`、`30m`、`60m`、`1d`、`1w`、`1mo`；
- `range`：`today`、`5d`、`60d`、`6mo`、`ytd`、`1y`、`5y`、`all`；
- `adjustment`：`none`、`qfq`、`hfq`。

返回：

- 时间；
- 开盘价；
- 最高价；
- 最低价；
- 收盘价；
- 成交量；
- 成交额；
- 是否为未完成柱；
- 数据源；
- 最后更新时间；
- 质量状态。

### 11.5 初始化与数据状态

`GET /api/system/data-status`

返回股票主数据、日 K 回补、快照采集和分钟 K 服务状态。该接口第一版只用于页面状态提示和排错，不增加单独侧栏菜单。

## 12. 页面状态与交互

### 12.1 列表页

- 首次加载显示骨架屏；
- 搜索输入采用短延迟防抖；
- 行情刷新时不清空旧列表；
- 新数据到达后原位更新价格；
- 数据超过两分钟未更新时显示“数据可能已过期”；
- 休市时显示最后交易时间；
- 搜索无结果时显示明确空状态；
- 点击任意股票行进入详情页。

### 12.2 详情页

- 默认显示“日 K、近 60 日”；
- 点击“今日”切换为当天原生 1 分钟 K；
- 周期切换保留当前股票；
- 图表缩放不触发页面整体缩放；
- 悬浮提示显示单柱完整信息；
- 当前动态分钟柱采用明确状态提示；
- 获取失败时保留本地已有 K 线并显示错误提示。

## 13. 容错与限流

### 13.1 请求策略

- 全市场快照一分钟最多请求一次；
- 同类请求采用互斥锁，避免重入；
- 超时后进行少量重试并增加随机退避；
- 不在失败时无限快速重试；
- 历史回补采用低并发和可续传队列；
- 单股详情请求使用短时缓存并合并并发请求。

### 13.2 校验规则

- 股票代码必须能映射到已知市场；
- 同一批快照代码不得重复；
- 数据条数明显低于近期正常值时拒绝覆盖最新行情；
- 价格、成交量和成交额不能出现无法解释的负值；
- 市场时间不得无条件使用本地当前时间替代；
- 不同来源单位必须在适配器中统一；
- 所有写入必须幂等。

### 13.3 降级表现

- 主实时源失败：显示上一批行情和过期状态；
- 部分股票缺失：保留这些股票上一批有效数据并标记缺失；
- 分钟 K 获取失败：继续显示本地缓存，不用全市场快照合成原生 K；
- 历史回补失败：记录断点并在后续低频重试；
- 本地存储失败：停止继续写入，返回明确系统错误，避免静默丢失。

## 15. 验收标准

第一版同时满足以下条件才算完成：

1. 本地一条命令可启动前后端开发环境；
2. 列表页可以展示沪深京 A 股并支持分页；
3. 可以按代码或名称搜索；
4. 交易时段列表每分钟读取一批新快照；
5. 页面显示最后更新时间和数据状态；
6. 点击股票可以进入详情页；
7. 详情页可以展示日、周、月和多种分钟周期 K 线；
8. “今日”一根柱代表一分钟，并能每分钟追加；
9. K 线支持放大、缩小和拖动；
10. 默认回补最近 60 个交易日的日 K；
11. 已经取得的全市场快照和原生分钟 K 能在重启后继续读取；
12. 系统不把每分钟采样快照标记为原生分钟 K；
13. 上游接口失败时不会用零值覆盖有效数据；
14. 核心单元测试、集成测试和前端测试通过；
15. 页面样式与确认的 HeroUI 浅色平衡型设计一致，左侧只显示“全部股票”。

## 16. 后续演进顺序

MVP 完成后，按以下顺序扩展：

1. 增加第一个日线技术指标；
2. 增加第一个分钟技术指标；
3. 建立指标定义、参数和版本管理；
4. 增加条件筛选引擎；
5. 保存筛选命中原因与历史记录；
6. 增加提醒、自选股和回测；
7. 根据实际数据量和稳定性评估是否迁移到服务器或付费行情源。

每一步都继续保留数据来源、公式版本和质量状态，避免无法解释的筛选结果。
